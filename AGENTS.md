## Продуктовые решения

### Удалённая вкладка «Рабочее место поверителя» / «Провести поверку прибора»

**Статус:** УДАЛЕНА по продуктовому решению

**Обоснование:** Вкладка с ручным вводом точек поверки удалена, так как ею никто не будет пользоваться. Пользователи работают с калибраторами, которые сами генерируют протоколы поверки.

**Запрет:** НЕ ВОССТАНАВЛИВАТЬ эту вкладку ни в каком виде, не предлагать вернуть в roadmap.

**Альтернативы для регистрации поверок:**
- Импорт из Excel с обогащением из Госреестра
- Упрощённая регистрация (если будет реализована в будущем)

## Реализованный функционал

- [x] Учёт средств измерений (СИ) — CRUD
- [x] Контроль сроков поверок (расчёт следующей даты по МПИ)
- [x] Управление выдачей/возвратом приборов (складской учёт)
- [x] Справочники: персонал, отделы, склады
- [x] Генерация этикеток с DataMatrix-кодами (bwip-js)
- [x] Система уведомлений (контекст + хуки)
- [x] Конструкторы категорий и фильтров для СИ
- [x] Графики на Recharts
- [x] Статус "На поверке" для СИ
- [x] **Регистрация поверок** (двухшаговая модель: отправка → регистрация при возврате)
  - **Шаг 1: Отправка на поверку**
    - Кнопка "Отправить на поверку" в карточке СИ
    - Указание места поверки, ответственного, ожидаемой даты возврата
    - Статус СИ → 'verification', блокировка выдачи
    - Запись в OperationLog, событие в InstrumentHistory
    - Фильтр "На поверке" в реестре СИ
    - Подсветка просроченных возвратов (оранжевая)
    - Виджет на Сводке: "На поверке: N" + "просрочен возврат: M"
    - Одноразовое уведомление при M > 0 на старте
  - **Шаг 2: Регистрация поверки при возврате**
    - Кнопка "Вернулся с поверки" открывает форму с предзаполнением
    - Комментарий автоматически заполняется: "возврат с поверки, отправка <дата>, <место>"
    - Выбор СИ, дата поверки, поверитель, вердикт (годен/не годен)
    - Номер бумажного протокола, загрузка файла (PDF/DOCX → base64 в IndexedDB)
    - Дата следующей поверки (авто из МПИ, редактируема)
    - При сохранении: связка протокола с отправкой (completeSendoff)
    - Жизненный цикл СИ: pass → available + пересчёт дат, fail → repair
    - Запись в OperationLog, событие в InstrumentHistory
    - Печать A4-формы протокола регистрации
- [x] **Цифровой паспорт СИ**
  - История прибора в карточке СИ (протоколы, выдачи, операции)
  - Хронологический таймлайн с иконками и цветокодированием
  - Тесты агрегации истории
  - Источник событий поверки: форма "Регистрация поверок" (упрощённая, без ручного ввода точек)

### Приоритет 1: Госинтеграции
- [x] **Госреестр СИ** — автозаполнение карточки СИ по номеру в реестре ✅ РЕАЛИЗОВАНО
  - Сервис gosreestrService.ts с проксированием через /api/gosreestr
  - Хук useGosreestrSearch.ts с debounce 400ms и AbortController
  - UI в форме добавления СИ с выпадающим списком подсказок
  - Автозаполнение полей: name, type, manufacturer, intervalMonths
  - Статусы: "Данные из Госреестра", "Тип не действует", "Не найдено"
  - Скачивание PDF вложений (описание типа, методика поверки)
  - Rate limiting 1 req/s, кэширование (подсказки 24ч, карточки 7 дней)
  - Обработка ошибок без падения UI
  - Тесты: парсинг МПИ, маппинг, роутинг поиска, обработка ошибок
  - Vercel-функция с бинарным проксированием PDF и whitelist заголовков
- [x] **Импорт реестра СИ из Excel** ✅ РЕАЛИЗОВАНО
  - Страница импорта с загрузкой .xlsx/.xls файлов
  - Маппинг колонок под стандартный шаблон
  - Валидация: дубликаты заводских номеров, пустые обязательные поля
  - Пакетное обогащение через Госреестр (очередь 1 req/s)
  - Прогресс-бар с возможностью прерывания
  - Создание черновиков сотрудников если не найдены
  - Очередь «Уточнить дату поверки» для импортированных приборов
  - Тесты: парсинг xlsx, маппинг, валидация, дубликаты
- [x] **Корпоративное развёртывание (Интранет)** ✅ РЕАЛИЗОВАНО
  - Docker-конфигурация (Dockerfile multi-stage, docker-compose.yml)
  - Nginx с кэшированием Госреестра (30 дней, proxy_cache_lock)
  - Rate limiting 1r/s burst=5
  - Клиентский кэш в IndexedDB для оффлайн-работы
  - Настройка "Доступ к Госреестру: вкл/выкл" (персистентная)
  - Бейдж "Изолированный контур" при отключённом доступе
  - Бейдж "Данные из кэша от <дата>" при работе из кэша
  - Проверка свежести кэша при старте (лимит 20 проверок, очередь 1r/s)
  - Снапшот-импорт/экспорт (.json) для полностью изолированных сегментов
  - Страница настроек с управлением кэшем и снапшотами
  - Документация: схема топологии, заявка в ИБ, вариант с DMZ relay
  - Тесты: структура модуля indexedDBCache
- ФГИС АРШИН — экспорт результатов поверки в XML
